## 0. TL;DR

1. **SwiftPM:** `swift build --target <Target> --print-manifest-job-graph > /dev/null` runs the
   plugin's prebuild command and compiles nothing. The file it writes is byte-identical to the one
   `swift build --build-tests` writes, in 0.5 s warm and 6.8 s from clean against 9.8 s for the build,
   and it is written while the module does not compile (§1.1, §1.2).
2. **A plain `swift build` on SwiftPM 6.3.3 does not re-run the prebuild command after an edit inside
   an existing file**, so the generated file keeps the previous declarations; the graph run of item 1
   regenerates it (§1.4).
3. **Xcode 26.6 has no action that plans without building** (§1.5). Re-running the engine on the config
   the plugin synthesized at the target's last build — `output:` rewritten, `SOURCERY_PROJECT` set —
   writes a byte-identical file in 4.4 s on a cold cache and 0.15 s warm, and picks up an edit inside
   an existing file (§1.6).
4. **Proposed:** `scripts/print-mocks.sh <Target> [<Protocol> …]` in the skill, choosing the lane from
   the working directory and printing either each named protocol's `// MARK: -` block or the whole
   generated files. A 164-line prototype passed every row of §1.8 on the three probes.
5. A script under `skills/` is code by `kotlin-ksp-mocks` 003's precedent; D5 and D6 decide its
   classification and its gate, and both reach files outside `skills/`.

## 2. The shape this proposes

### 2.1 One command

```bash
"${CLAUDE_SKILL_DIR}/scripts/print-mocks.sh" <Target> [<Protocol> ...]
```

- Run from the directory holding `Package.swift`, or from the one holding the `.xcodeproj` or
  `.xcworkspace` or a directory above it. `<Target>` is the target carrying the config — the test
  target, for mocks.
- **The lane:** Xcode when `DERIVED_DATA` is set or the working directory holds a `*.xcodeproj` or
  `*.xcworkspace`; SwiftPM when it holds `Package.swift`; otherwise
  `print-mocks: run from the directory holding Package.swift or the .xcodeproj`, exit 1.
- **With protocol names:** each name's §1.7 block followed by a blank line. A name with no block prints
  `// <Protocol>: no mock generated for <Target>`, and the script exits 1 after printing the rest.
- **Without:** every `*.generated.swift` of the target, sorted, each after a `// <path>` line and
  followed by a blank line.
- No version literal; bash 3.2 (`/bin/bash` on macOS), so an empty array expands as
  `${a[@]+"${a[@]}"}`.

### 2.2 SwiftPM

1. `swift build --target <Target> --print-manifest-job-graph > /dev/null`, stderr kept. With
   `SCRATCH_PATH` set, `--scratch-path "$SCRATCH_PATH"` is added and step 4 reads under it instead of
   `.build` (D6's gate needs it).
2. If it fails and stderr contains `depends on the product 'SourcerySwiftCodegenPlugin' which requires
   macos`, run it again with `--triple "$(uname -m)-apple-ios-simulator" --sdk "$(xcrun --sdk
   iphonesimulator --show-sdk-path)"`. Any other failure prints stderr and exits 1 with
   `print-mocks: planning <Target> failed`.
3. On success, copy stderr's `warning:` lines to stderr, less the plugin's `Error running git command`.
4. Print `.build/plugins/outputs/*/<Target>/destination/SourcerySwiftCodegenPlugin/.generatedFiles/*/*.generated.swift`.
   None: `print-mocks: <Target> generated no file — …` (§1.8), exit 1.

Nothing is written outside `.build`, and the files printed are the ones the next build compiles
(§1.1).

### 2.3 Xcode

1. **The derived data:** `$DERIVED_DATA`; otherwise each
   `${DERIVED_DATA_ROOT:-$HOME/Library/Developer/Xcode/DerivedData}/*/info.plist` whose `WorkspacePath`
   (read with `/usr/libexec/PlistBuddy -c 'Print :WorkspacePath'`) has a directory, resolved with
   `pwd -P`, under the working directory's.
2. **The configs:** among those, the
   `Build/Intermediates.noindex/BuildToolPluginIntermediates/*/<Target>/SourcerySwiftCodegenPlugin/.sourceryConfigs`
   directory with the newest mtime; each `find` ends `|| true`. None: §1.8's `no configs the plugin
   synthesized …` line, exit 1. The files are listed with `find "$configs" -maxdepth 1 -type f`, which
   includes dotfiles.
3. **The engine:** `$SOURCERY_ENGINE`; else, from the first quoted `…/templates/*.swifttemplate` in the
   configs, `<dir>/sourcery/bin/sourcery` when `templates/`'s parent `<dir>` holds `info.json` (an
   artifact bundle), or the first `*/sourcery/bin/sourcery` under the path's prefix before
   `/checkouts/` plus `/artifacts`; else under `<DerivedData>/SourcePackages/artifacts`. Not executable:
   `print-mocks: no Sourcery engine found for <DerivedData> — set SOURCERY_ENGINE`, exit 1.
4. **The copy:** each config to `<DerivedData>/Build/Intermediates.noindex/PrintMocks/<Target>/.configs/<name>`
   with the column-0 `output:` line replaced by `output: "<PrintMocks>/<Target>/<stem>"`. `<stem>` is the
   file name without its leading dots and its last extension — `directoryName(for:)` at
   `SourcerySwiftCodegenPlugin.swift:319-330`. `<PrintMocks>/<Target>` is removed first.
5. **The run:** `env SOURCERY_PROJECT=<$SOURCERY_PROJECT, or the directory of WorkspacePath>
   GIT_ROOT=<git -C <project> rev-parse --show-toplevel> SOURCERY_TEMPLATES=<the templates directory of
   step 3> SOURCERY_OUTPUT_DIR=<the copy's output> <engine> --config <copy> --cacheBasePath
   <PrintMocks>/.cache --buildPath <PrintMocks>/.build --quiet`. A non-zero exit prints the engine's
   output and `print-mocks: the engine failed on <name> for <Target>`, exit 1.
6. **The print:** `<PrintMocks>/<Target>/*/*.generated.swift`, as §2.1 states.

The four variables are what the Xcode half of the plugin exports: `SOURCERY_PROJECT` and `GIT_ROOT` at
`SourcerySwiftCodegenPlugin.swift:1126-1141`, `SOURCERY_TEMPLATES` at `:792`, `SOURCERY_OUTPUT_DIR` at
`:851`. It leaves out `SOURCERY_TARGET_<t>_DEP_*`, built from dependency edges the comment at
`:1185-1194` records as measured empty.

A run reads the sources in the directories the last build's config lists, as they are now. A source
directory added to the target, a changed config or a new package dependency reaches it after the next
build.

**Superseded in part by §8.2:** step 3's `$SOURCERY_ENGINE` is `PRINT_MOCKS_ENGINE`, and each lookup
in steps 2 and 3 that can find nothing ends `|| true`.

## 3. Decisions

None is ruled. Each lists the option recommended first.

**Ruled on 2026-09-13 — §7.1:** every decision below.

### D1 — how the SwiftPM lane reaches the plugin

- **(a) `--print-manifest-job-graph` (recommended).** A public flag, present in the 5.9 source and on
  6.3.3, and it answered under both build systems (§1.1, §1.3). Cost: its purpose is to emit Graphviz,
  and that it runs the prebuild commands without building is a property of `plan()`, not a documented
  contract. D6 (a)'s plugin-lane gate reports a toolchain that changes it.
- **(b) The Xcode mechanism of §2.3 for SwiftPM too**, on `.build/plugins/outputs/…/.sourceryConfigs`.
  One mechanism for both lanes. Costs: a prior build; the SwiftPM configs may name `SOURCERY_PACKAGE`
  and `SOURCERY_TARGET_*` (`:1015-1031`), which the script would derive from
  `swift package describe`; and step b of §1.4 leaves that config as stale as the mock.
- **(c) A command plugin, `swift package print-mocks`**, in `Plugins/` and `Package.swift`. Documented
  API. Costs: a release before any adopter has it, and a product every adopter's graph resolves. Not
  measured.

### D2 — how the Xcode lane reaches the engine

- **(a) The re-run on the last synthesized config, §2.3 (recommended).** 0.15 s warm. Costs: one
  earlier build of the target in that derived data, and the script restates the four variables of §2.3
  — D6 (a)'s SC6 extension compares them with the plugin source.
- **(b) Prose only: build, then read `.generatedFiles/`.** No script. The plugin writes before the
  target compiles and while the build fails (§1.5), but a build that succeeds costs the whole build:
  11.2 s clean on a one-file probe.
- **(c) Locate derived data with `xcodebuild -showBuildSettings`** instead of `info.plist`: 1.4–2.3 s a
  call, and it needs a scheme name. A fallback if `WorkspacePath` stops being written.

### D3 — which caches the Xcode re-run uses

- **(a) Its own `PrintMocks/.cache` and `PrintMocks/.build` (recommended).** Writes nothing in the
  plugin's work directory. Cost: 4.4 s on the first run in each derived data directory.
- **(b) The plugin's `.sourceryCaches` and `.sourceryBuild`.** 0.09 s on the first run. Cost: it writes
  into directories an Xcode build running at the same time writes too; that concurrency was not measured.

### D4 — what it prints

- **(a) The named protocols' blocks, or every whole file when none is named (recommended).** A test
